# ADR: freee の認証情報は、変わらない値を 1Password に、トークンを状態ファイルに置く

freee の API を呼ぶための認証情報について、クライアント ID とシークレットは 1Password、トークンは所有者のマシンの状態ファイルに置くという決定を記録する。

- 読者: 開発者
- 状態: 採用
- 決定日: 2026-10-03

用語は PRD 0007 と同じ意味で使う。
`kintai` は、ADR 0007 で Rust で書くと決めた CLI を指す。
「すべて」「最小限」は、PRD 0001 が定める導入範囲を指す。

## 背景

ADR 0008 で、`kintai` が freee の API を呼んで請求書の下書きを作ると決めた。
freee の API を呼ぶには、OAuth の認証情報が要る。
認証情報には、変わらない値であるクライアント ID とシークレットと、更新のたびに書き換わるアクセストークンとリフレッシュトークンがある。
PRD 0007 では、認証の準備とその情報の管理を所有者が引き受けると決めた。
そのため、それぞれの認証情報を置く場所を決める必要がある。

## 制約

PRD 0007 と ADR 0008 から、選べる案は次の条件を満たす必要がある。

- 認証情報を、このリポジトリに置かない。
- 更新されたトークンを、`kintai` が自分で書き戻せる。
- 導入範囲「すべて」で使える。

## 決定

クライアント ID とシークレットは 1Password に置き、`kintai` が `op read` で読む。
1Password の参照先は、設定で指定する。

アクセストークンとリフレッシュトークンは、権限を 600 にしたファイルとして `$XDG_STATE_HOME/kintai/`（既定は `~/.local/state/kintai/`）の下に置く。
`kintai` は、トークンを更新するたびにこのファイルへ書き戻す。

## 決定理由

- 変わらないシークレットが、平文のファイルで残らない。
- 書き換わるトークンは、1Password にサインインしなくても書き戻せる。
- トークンのファイルをなくしても、再認証すれば元に戻せる。

## 代替案

次の案は、それぞれの理由で採らない。

- すべてを 1Password に置く案: トークンを更新するたびに、1Password のサインインが要る。
- すべてをファイルに置く案: シークレットが平文で残る。
- OS のキーリングに置く案: WSL や macOS など、マシンによって振る舞いが変わる。

## 結果

- `kintai` で freee の API を呼ぶには、1Password CLI とそのサインインが要る。
- トークンは平文のファイルで残り、その保護はファイルの権限に頼る。
- 最初の認証と再認証のための操作を、`kintai` に用意する。
