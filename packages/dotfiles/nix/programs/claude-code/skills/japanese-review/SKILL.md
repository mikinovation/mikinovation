# japanese-review: tanteki と yomiyasu の組でレビューするスキル

日本語の文書を、tanteki → yomiyasu → textlint の再実行の順に通す。tanteki と yomiyasu を別々に呼ばず、必ずこのスキルから組で呼ぶ。

二つのスキルは役割が違う。

| スキル | 役割 |
|---|---|
| tanteki | 文書の種類に合う構成と内容を整え、textlint で検査する |
| yomiyasu | 比喩、曖昧な主語、装飾など、AI が書いたような不自然な文を直す |

yomiyasu は、文体を調整する他のスキルと同時に使うと指示が干渉すると注意している。そのため二つを同時に適用せず、順に一つずつ呼ぶ。

## 呼び出し元から受け取るもの

| 項目 | 内容 |
|---|---|
| 依頼 | `執筆`（材料から新しく書く、既存の文書を更新する）または `推敲`（書かれた文書を直す） |
| 対象 | 文書の絶対パス。執筆では保存先とファイル名の規則 |
| 文書の種類 | 文書の種類と、textlint の `--type` |
| 立場 | yomiyasu に渡す文書の立場。`勧め`、`決まり`、`説明` のいずれか |
| 変えないこと | 見出し、構成、ID、表、書式など、呼び出し元が固定したもの |
| 原資料 | 確定した材料や、読んだコミットと差分 |
| 構成と形式 | 執筆で守らせる構成と形式。呼び出し元が指定した場合だけ |

足りない項目があれば、呼び出し元の文脈から補う。補えない場合だけユーザーに尋ねる。

## 手順

### 1. tanteki に執筆または推敲を渡す

`Skill` ツールで `tanteki` を呼び、受け取ったものをすべて渡して、依頼に応じて文書を執筆または推敲させる。文書は対象のパスに保存させる。

tanteki の textlint の結果と、内容の問題として残ったものを控える。

### 2. yomiyasu で不自然な日本語を直す

書き直す前に、tanteki が保存した文書を一時ファイル（例: `$(mktemp -d)/before.md`）に写す。yomiyasu の差分検査で元の文として使う。

`Skill` ツールで `yomiyasu` を呼び、次を渡す。

- 対象: 文書の絶対パス。依頼は文書全体を読みやすくすることで、モードはフルモードとする
- 立場: 受け取った立場。差分検査の `--stance` にも使わせる
- 元の文: 写した一時ファイルの絶対パス
- 変えないこと: 受け取った変えないことに加え、Markdown の構成と書式（見出し、表、箇条書きの構造、チェックボックス、コードブロック、インラインコード、ID、リンク、Mermaid の図）。直すのは文の言い回しだけとする。箇条書きを地の文にまとめない
- 英数字と日本語の間の半角空白は原文のまま残す。リポジトリの既存の文書と表記をそろえるためである
- 表の各セルを60文字以内に収める。tanteki の合格条件を崩さないためである
- 原資料: 受け取った原資料。原資料にない事実を加えない
- 書き直した本文を対象のファイルに上書きして保存する。「変えたところ」「残したAIっぽいところ」「書き手に確かめたい点」はファイルに書かず、結果として返す
- Git 操作、送信、投稿は行わない

### 3. textlint を再実行する

yomiyasu が文書を書き換えたため、tanteki の textlint だけを再実行する。tanteki で書き直しはさせない。

```sh
"$(readlink -f ~/.claude/skills/tanteki/scripts/lint.mjs)" --type <文書の種類の --type> <文書の絶対パス>
```

`scripts/lint.mjs` は symlink 経由で呼ぶと検査せずに終了コード0を返すため、`readlink -f` で解決したパスで実行する。

指摘が出た場合は、指摘された文だけを直す。yomiyasu が直した箇所は、意味と読みやすさを保ったまま指摘を解消する。直したら一度だけ再実行し、それでも残る指摘は結果に書く。tanteki と yomiyasu を呼び直して往復させない。

検査を通すために、ルールを無効にしたり、問題のある文をコードや引用へ移したりしない。検査を実行できなかった場合は、未検証と結果に書く。

### 4. 結果を返す

呼び出し元に次を返す。文書の本文には混ぜない。

```
対象: <文書の絶対パス>
tanteki: <済 / 残った問題>
yomiyasu: <済 / 飛ばした（理由）>
textlint（yomiyasu の後）: <合格 / 残った指摘 / 未検証（理由）>
変えたところ: <yomiyasu が返した主な変更>
書き手に確かめたい点: <yomiyasu が返した点。なければ「なし」>
```

呼び出し元は、この結果を下書きや材料と一緒に示す。

## 飛ばす場合

- 文書が日本語でない場合は、このスキルを使わない。tanteki と yomiyasu はどちらも日本語の文書だけを対象とする
- `Skill` ツールで `yomiyasu` を呼べない場合は、手順2を飛ばし、手順3も飛ばす。飛ばしたことを結果に書く
- `Skill` ツールで `tanteki` を呼べない場合は、このスキル全体を飛ばし、飛ばしたことを呼び出し元に返す

## このスキルで扱わないこと

- 文書の材料集めとユーザーとの合意（呼び出し元の領分）
- 保存先とファイル名の決定（呼び出し元の領分）
- Git 操作、PR の作成、GitHub への投稿
