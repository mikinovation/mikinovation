# japanese-review: tanteki と yomiyasu の組でレビューするスキル

日本語の文書を、tanteki → yomiyasu → textlint の再実行の順に通す。

二つのスキルは役割が違う。

| スキル | 役割 |
|---|---|
| tanteki | 文書の種類に合う構成と内容を整え、textlint で検査する |
| yomiyasu | 比喩、曖昧な主語、装飾など、AI が書いたような不自然な文を直す |

yomiyasu は、文体を調整する他のスキルと同時に使うと指示が干渉すると注意している。同じ会話で順に呼んでも、tanteki の指示は会話に残る。そのため yomiyasu はサブエージェントで実行し、tanteki の指示が届かないようにする。あわせて、yomiyasu には文の言い回しだけを直させ、構成と書式は tanteki の結果を保たせる。

## 呼び出し元から受け取るもの

| 項目 | 内容 |
|---|---|
| 依頼 | `執筆`（新規に書く、既存の文書を更新する）または `推敲` |
| 対象 | 文書の絶対パス。執筆では保存先とファイル名の規則 |
| 文書の種類 | 文書の種類。textlint の `--type` が決まっていればそれも |
| 立場 | yomiyasu に渡す文書の主な立場。`勧め`、`決まり`、`説明` のいずれか |
| 変えないこと | 見出し、構成、ID、表、書式など、呼び出し元が固定したもの |
| 原資料 | 確定した材料や、読んだコミットと差分 |
| 構成と形式 | 執筆で守らせる構成と形式。呼び出し元が指定した場合だけ |

足りない項目があれば、呼び出し元の文脈から補う。補えない場合だけユーザーに尋ねる。

## 手順

### 1. tanteki に執筆または推敲を渡す

対象のファイルがすでにある場合は、tanteki を呼ぶ前に一時ファイル（例: `$(mktemp -d)/original.md`）に写す。手順2で、今回変わった範囲を見分けるために使う。

`Skill` ツールで `tanteki` を呼び、受け取ったものをすべて渡して、依頼に応じて文書を執筆または推敲させる。文書は対象のパスに保存させる。

tanteki の結果から次を控える。

- 検査に使った `--type`。呼び出し元が指定していない場合は、tanteki が選んだ値を使う
- textlint の指摘。指摘がなければ「なし」
- 内容の問題として残ったもの

### 2. yomiyasu をサブエージェントで実行する

書き直す前に、tanteki が保存した文書を一時ファイル（例: `$(mktemp -d)/before.md`）に写す。yomiyasu の差分検査で元の文として使う。

yomiyasu に直させる範囲を決める。

| 場合 | 範囲 |
|---|---|
| 新規の執筆 | 文書全体 |
| 推敲 | 文書全体 |
| 既存の文書の更新 | 手順1で写した文書と比べて、今回追加・変更された節だけ |

更新で変わった節がなければ、手順2と手順3を飛ばす。

`Agent` ツールでサブエージェントを起動し、`Skill` ツールで `yomiyasu` を呼ばせる。tanteki は呼ばせない。サブエージェントはこの会話を読めないため、依頼文に次をすべて書く。原資料は、ファイルのパスか本文で渡す。

- 対象: 文書の絶対パスと、直させる範囲。依頼は範囲を読みやすくすることで、モードはフルモードとする。範囲の外は一字も変えない
- 立場: 受け取った主な立場。差分検査の `--stance` に使わせる。働きの違う文や節は、その文の働きに合う文末のまま残す
- 元の文: 写した一時ファイルの絶対パス
- 変えないこと: 受け取った変えないことに加え、Markdown の構成と書式（見出し、表、箇条書きの構造、チェックボックス、コードブロック、インラインコード、ID、リンク、Mermaid の図）。直すのは文の言い回しだけとする。箇条書きを地の文にまとめない
- 半角空白: 英数字と日本語の間の半角空白は原文のまま残す。リポジトリの既存の文書と表記をそろえるためである
- 表: 各セルを60文字以内に収める。tanteki の合格条件を崩さないためである
- 原資料: 受け取った原資料。原資料にない事実を加えない
- 保存: 書き直した本文を対象のファイルに上書きして保存する。「変えたところ」「残したAIっぽいところ」「書き手に確かめたい点」はファイルに書かず、サブエージェントの結果として返す
- Git 操作、送信、投稿は行わない

### 3. textlint を再実行する

yomiyasu が文書を書き換えたため、tanteki の textlint だけを再実行する。tanteki で書き直しはさせない。`--type` には手順1で控えた値を使う。

```sh
"$(readlink -f <tanteki のスキルルート>/scripts/lint.mjs)" --type <手順1で控えた --type> <文書の絶対パス>
```

tanteki のスキルルートは、tanteki の `SKILL.md` があるディレクトリである。Nix で配置した環境では `~/.claude/skills/tanteki` にある。`scripts/lint.mjs` は symlink 経由で呼ぶと検査せずに終了コード0を返すため、`readlink -f` で解決したパスで実行する。tanteki の `SKILL.md` が `node` を付けて実行するよう指示している環境では、その指示に従う。

手順1で控えた指摘と比べ、yomiyasu の後に新しく出た指摘だけを直す。手順1から残っている指摘は直さず、そのまま結果に書く。

新しい指摘は、指摘された文だけを、意味と読みやすさを保ったまま直す。直したら一度だけ再実行し、それでも残る指摘は結果に書く。tanteki と yomiyasu を呼び直して往復させない。

検査を通すために、ルールを無効にしたり、問題のある文をコードや引用へ移したりしない。検査を実行できなかった場合は、未検証と結果に書く。

### 4. 結果を返す

呼び出し元に次を返す。文書の本文には混ぜない。

```
対象: <文書の絶対パス>
tanteki: <済 / 残った問題>
yomiyasu: <済（範囲） / 飛ばした（理由）>
textlint（yomiyasu の後）: <合格 / 新しい指摘が残った / 未検証（理由）>
textlint（tanteki から残った指摘）: <なし / 指摘>
変えたところ: <yomiyasu が返した主な変更>
書き手に確かめたい点: <yomiyasu が返した点。なければ「なし」>
```

呼び出し元は、この結果を下書きや材料と一緒に示す。

## 飛ばす場合と止める場合

- 文書が日本語でない場合は、このスキルを使わない。tanteki と yomiyasu はどちらも日本語の文書だけを対象とする
- `Agent` ツールが使えない場合は、`Skill` ツールで `yomiyasu` を直接呼ぶ。tanteki の指示と干渉するおそれがあることを結果に書く
- `yomiyasu` を呼べない場合は、手順2と手順3を飛ばし、飛ばしたことを結果に書く
- `Skill` ツールで `tanteki` を呼べない場合は、依頼で扱いを分ける
  - 推敲: このスキル全体を飛ばし、飛ばしたことを呼び出し元に返す。呼び出し元は手元の下書きのまま進める
  - 執筆: 文書を書けないため、ここで止めて、tanteki を呼べないことを呼び出し元に返す。tanteki を通さずに執筆しない

## このスキルで扱わないこと

- 文書の材料集めとユーザーとの合意（呼び出し元の領分）
- 保存先とファイル名の決定（呼び出し元の領分）
- Git 操作、PR の作成、GitHub への投稿
