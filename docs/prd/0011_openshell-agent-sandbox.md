# PRD: OpenShell によるエージェント実行の保護

Claude Code をセキュリティの仕組みがないまま動かしている課題について、問題と仮説を整理する。
この課題に時間をかけるべきかを判断する材料にする。

- 読者: 開発者
- 段階: 1. 出発点（問題と仮説を整理した。問題の検証は未着手）

この PRD の用語は次の意味で使う。

- OpenShell: NVIDIA が公開している、AI エージェントを安全に動かすためのサンドボックス実行環境。
- 作業ディレクトリ: エージェントに作業させるリポジトリのディレクトリ。

## 課題

### 問題と根拠

所有者は、Claude Code の実行の安全性と再現性に課題があると考えている。
この問題は仮説であり、まだ検証していない。

所有者が避けたい事態は次の4つである。
このうち最も優先するのは、秘密情報の漏えいである。

1. 秘密情報の読み取りや外部への送信。API キー、SSH 鍵、`.env` などを含む。
2. 破壊的なコマンドによるファイルやリポジトリの損失。`rm -rf` や `git push --force` などを含む。
3. 許可していない外部ホストとの通信。
4. 作業ディレクトリの外にあるファイルへの書き込み。

### なぜ今か

現状、これらの事態をセキュリティの面から防ぐ仕組みがない。
そのため、早急に対策が必要である。

### 対象となる利用者

所有者が個人開発と dotfiles の環境で使う Claude Code を対象とする。
ほかのコーディングエージェントは対象にしない。

個人で使う環境のため、ほかの関係者からの意見は集めない。

### 仮説

OpenShell 上で Claude Code を動かせば、普段の開発の使い勝手を大きく損なわずに、上記の4つの事態を防げる。

## 未解決の問い

段階2へ進む前に、次の問いに答える。

1. 上記の4つの事態は、現状の環境で実際にどの程度起こりうるか。ヒヤリハットはあったか。
2. Claude Code にもともとある権限設定やサンドボックス機能だけでは足りないのか。
3. OpenShell を導入すると、開発の速度や使い勝手はどれだけ落ちるか。
