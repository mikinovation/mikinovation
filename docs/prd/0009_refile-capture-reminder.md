# PRD: 受信箱への定期的なメモの促し

所有者が、作業中に考えたことや気付きを受信箱に書かないまま忘れてしまう課題について、問題と仮説を整理し、まず中断の小さい通知で解くための要求を定める。

- 読者: 開発者
- 段階: 4. 設計（解決案を比べて要求を定めた。受入条件と展開計画は未着手）

この PRD の用語は次の意味で使う。

- 受信箱: 分類前のメモやタスクをいったん置くファイル。PRD「ノートとタスクの管理」（`docs/prd/0006_note-taking.md`）で定める。
- 促し: 一定の間隔で、所有者に受信箱へメモを書くよう求めること。
- 一時停止: 所有者が選んだ時間だけ、促しを止めること。

## 課題

### 問題と根拠

所有者は、受信箱を1回の操作で開ける（PRD 0006 の要求8）。
それでも、作業中に考えたことや気付きを受信箱に書かないまま忘れてしまう。

所有者の申告では、書き忘れは毎日、毎時間のように起きる。
意思の力で書こうとしても続かない。
書き忘れた考えを思い出したり、同じことを考え直したりするために、所有者の時間が失われている。
この根拠は所有者の申告であり、件数を測ってはいない。

### なぜ今か

受信箱の運用が PRD 0006 で整った。
次の段階として、受信箱に書く習慣をつけたい。

### 対象となる利用者

リポジトリの所有者本人だけを対象とする。

### 仮説

- 15分ごとに促されれば、受信箱に残るメモの件数が増える。
- 15分ごとに作業を中断されても、作業の効率は落ちない。
- 通知だけでも、受信箱に残るメモの件数が導入前より増える。

### 提供する価値

所有者は、作業中の考えを受信箱に残し、後から拾える。
書くかどうかを、所有者が意識しなくてよくなる。
受信箱のメモから、1日の作業の流れをたどれる。

### 対象外

- 受信箱のメモを分類して移す作業。
- スマートフォンなど、ほかの端末からメモを書くこと。
- 促しの間隔を、作業の状況に合わせて自動で長くしたり短くしたりすること。
- エディター以外で作業しているときに促すこと。

### 制約とトレードオフ

所有者は、次のことを受け入れる。

- メモを書く習慣をつける代わりに、15分ごとに作業を中断される。
- エディターの中で促す代わりに、エディターを開いていないときは促されない。

### 成功条件

受信箱のメモの件数が、導入前より増える。
数値目標は設けない。

### 計測と学習の計画

導入前と導入後の各2週間について、受信箱に追加された見出しの数を、受信箱を置くリポジトリの Git 履歴から数えて比べる。
中断がつらいと感じた場合は所有者が記録し、促しの間隔や方法を見直す材料にする。

## 解決策

### 解決案とトレードオフ

次の3案を比べ、案Aを採った。

| 案 | 振る舞い | 利点 | 欠点 |
|---|---|---|---|
| A. 通知だけ | エディターに通知が出る | 中断が最も小さい | 無視できる |
| B. 入力欄を開く | 入力欄が開き、書かずに閉じられる | 書き始める手間がない | 閉じる癖がつくおそれがある |
| C. 書くまで閉じられない | 1件書くまで入力欄を閉じられない | 意思の力に頼らない | 中断が最も大きい |

根拠では意思の力で書こうとしても続かないとしており、案Aは最後には意思の力に頼る。
それでも、まず中断の最も小さい案Aで試す。
3つ目の仮説が外れた場合は、案Bまたは案Cに切り替える。

### 要求

| # | 要求 |
|---|---|
| 1 | 最後にメモを書いてから15分たつと、エディターに通知が出る |
| 2 | 通知は、所有者が閉じるかメモを書くまで残る |
| 3 | 1回の操作で、日時付きの見出しを書く入力欄が開く |
| 4 | 書いたメモは、日時付きの見出しとして受信箱に追加される |
| 5 | 受信箱の見出しが1件増えると、15分を数え直す |
| 6 | 一時停止でき、止めるたびに長さを選べる |
| 7 | 一時停止の時間が過ぎると、促しが自動で再開する |

要求5は、メモの書き方を問わない。
受信箱を直接開いて書いた場合も、数え直す。
