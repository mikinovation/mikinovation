# PRD: refile.org への定期的なメモの促し

所有者が、作業中に考えたことや気付きを `refile.org` に書かないまま忘れてしまう課題について、問題と仮説を整理し、まず中断の小さい通知で解くための要求と受入条件を定める。

- 読者: 開発者
- 段階: 5. デリバリー（要求と受入条件を確定した。実装は未着手）

この PRD の用語は次の意味で使う。

- `refile.org`: 分類前のメモやタスクをいったん置くファイル。PRD「ノートとタスクの管理」（`docs/prd/0006_note-taking.md`）で定める。
- 促し: 一定の間隔で、所有者に `refile.org` へメモを書くよう求めること。
- 一時停止: 所有者が選んだ時間だけ、促しを止めること。
- 「すべて」「最小限」: 開発環境の導入範囲。PRD「開発環境の導入」（`docs/prd/0001_environment-setup.md`）で定める。

## 課題

### 問題と根拠

所有者は、`refile.org` を1回の操作で開ける（PRD 0006 の要求8）。
それでも、作業中に考えたことや気付きを `refile.org` に書かないまま忘れてしまう。

所有者の申告では、書き忘れは毎日、毎時間のように起きる。
意思の力で書こうとしても続かない。
書き忘れた考えを思い出したり、同じことを考え直したりするために、所有者の時間が失われている。
この根拠は所有者の申告であり、件数を測ってはいない。

### なぜ今か

`refile.org` の運用が PRD 0006 で整った。
次の段階として、`refile.org` に書く習慣をつけたい。

### 対象となる利用者

リポジトリの所有者本人だけを対象とする。

### 仮説

- 15分ごとに促されれば、`refile.org` に残るメモの件数が増える。
- 15分ごとに作業を中断されても、作業の効率は落ちない。
- 通知だけでも、`refile.org` に残るメモの件数が導入前より増える。

### 提供する価値

所有者は、作業中の考えを `refile.org` に残し、後から拾える。
書くかどうかを、所有者が意識しなくてよくなる。
`refile.org` のメモから、1日の作業の流れをたどれる。

### 対象外

- `refile.org` のメモを分類して移す作業。
- スマートフォンなど、ほかの端末からメモを書くこと。
- 促しの間隔を、作業の状況に合わせて自動で長くしたり短くしたりすること。
- エディター以外で作業しているときに促すこと。

### 制約とトレードオフ

所有者は、次のことを受け入れる。

- メモを書く習慣をつける代わりに、15分ごとに作業を中断される。
- エディターの中で促す代わりに、エディターを開いていないときは促されない。

### 成功条件

`refile.org` のメモの件数が、導入前より増える。
数値目標は設けない。

### 計測と学習の計画

導入前と導入後の各2週間について、`refile.org` に追加された見出しの数を、`refile.org` を置くリポジトリの Git 履歴から数えて比べる。
中断がつらいと感じた場合は所有者が記録し、促しの間隔や方法を見直す材料にする。

## 解決策

### 解決案とトレードオフ

次の3案を比べ、案Aを採った。

| 案 | 振る舞い | 利点 | 欠点 |
|---|---|---|---|
| A. 通知だけ | エディターに通知が出る | 中断が最も小さい | 無視できる |
| B. 入力欄を開く | 入力欄が開き、書かずに閉じられる | 書き始める手間がない | 閉じる癖がつくおそれがある |
| C. 書くまで閉じられない | 1件書くまで入力欄を閉じられない | 意思の力に頼らない | 中断が最も大きい |

「問題と根拠」では、意思の力で書こうとしても続かないとしている。
案Aは、最後には意思の力に頼る。
それでも、まず中断の最も小さい案Aで試す。
3つ目の仮説が外れた場合は、案Bまたは案Cに切り替える。

### 要求と受入条件

各要求と、その要求を受け入れる条件は次のとおり。

| # | 要求 | 受入条件 |
|---|---|---|
| 1 | 最後にメモを書いてから15分たつと、エディターに通知が出る | 起動または最後のメモから15分たつと通知が出る。15分たつ前には出ない |
| 2 | 通知は、所有者が閉じるかメモを書くまで残る | 閉じる操作をするかメモを書くまで、通知が消えない |
| 3 | 1回の操作で、日時付きの見出しを書く入力欄が開く | 1回の操作で入力欄が開き、メモの本文を書ける |
| 4 | 書いたメモは、日時付きの見出しとして `refile.org` に追加される | 書いたメモが `* [日時] 本文` の形で `refile.org` に追加される |
| 5 | `refile.org` の見出しが1件増えると、15分を数え直す | `refile.org` の見出しが増えると、その時刻から15分を数え直す |
| 6 | 一時停止でき、止めるたびに長さを選べる | 30分、1時間、2時間から長さを選べ、その間は通知が出ない |
| 7 | 一時停止の時間が過ぎると、促しが自動で再開する | 止めた時間が過ぎると、その時刻から15分後に通知が出る |

要求1の15分は、起動してからメモを1件も書いていない場合、起動した時刻から数える。
エディターを複数開いている場合は、エディターごとに別々に数えて通知する。

要求4の見出しは、`* [2026-10-04 Sun 14:30] メモの本文` のように、レベル1の見出しの先頭に日時を置く。

要求5は、メモの書き方を問わない。
`refile.org` を直接開いて書いた場合も、数え直す。

### 成功条件の測定方法

`refile.org` を置くリポジトリの Git 履歴から、`refile.org` に追加された見出しの数を数える。
導入日より前の2週間と、導入日からの2週間を、コミット日で分けて比べる。

コミットする前に別のファイルへ移した見出しは数えられない。
この漏れは導入の前と後の両方で起きるため、比べるうえでは受け入れる。

### 展開計画

所有者のマシンだけに提供する。
開発環境を「すべて」と「最小限」のどちらの範囲で導入しても、すべての要求を満たす。
段階的な公開はしない。
変更は、各マシンで開発環境の導入をやり直した時点で、そのマシンに反映される。
