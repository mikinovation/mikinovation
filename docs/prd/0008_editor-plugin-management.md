# PRD: エディターのプラグイン管理

所有者が、どのマシンでも同じ版のプラグインを揃え、版を上げる時期を自分で決められるようにするための要求と受入条件を定める。

- 読者: 開発者
- 段階: 5. デリバリー（要求と受入条件を確定し、実装済み）

この PRD の用語は次の意味で使う。

- エディター: PRD 0002「エディターの導入」で導入するエディター。
- プラグイン: エディターに機能を加える拡張。
- 版の記録: 各プラグインの版を書き留め、リポジトリに置く記録。
- 導入操作: PRD 0001「開発環境の導入」で定める、開発環境を導入する操作。

## 課題

### 問題と根拠

プラグインの版がマシンごとにずれると、同じ設定でもマシンによって挙動が変わり、一部のマシンではエラーが出る。
また、プラグインをマシンごとに手作業で揃えるには手間がかかる。

### 対象となる利用者

リポジトリの所有者本人だけを対象とする。

### 提供する価値

所有者は、どのマシンでも同じ版のプラグインを使える。
プラグインの版を上げる時期を、所有者が決められる。
プラグインの新しい版が出たことを、週に1回まとめて知ることができる。
使わないプラグインを起動時に読み込まないため、エディターが速く起動する。

### 対象外

- 開発環境の導入で設定される環境変数がない状態で起動したときに、プラグインの版を固定すること。
- あるマシンで更新した版の記録を、プラグインを取得済みの既存のマシンへ反映すること。

### 制約とトレードオフ

所有者は、次のことを受け入れる。

- どのマシンでも版を揃える代わりに、所有者が版を更新するまで新しい版は入らない。
- 初回起動でプラグインを自動で揃える代わりに、初回起動にはネットワークへの接続が必要になる。
- 新しい版をまとめて知らせる代わりに、新しい版が出てから知るまでに最大で1週間かかる。

### 成功条件

新規のマシンまたは復旧したマシンで、既存マシンと同じ版のプラグインが揃い、起動時にエラーが出ない。
数値目標は設けない。

### 計測と学習の計画

新規のマシンへの導入と、壊れたマシンの復旧のたびに、成功条件を満たしたかを確かめる。
手作業での設定が必要になった場合や、不具合が生じた場合は記録し、要求と対象外を見直す材料にする。

## 解決策

### 要求と受入条件

各要求と、その要求を受け入れる条件は次のとおり。

| # | 要求 | 受入条件 |
|---|---|---|
| 1 | 初回起動時に、所有者が操作せずに全プラグインが揃う | 初回起動のあと、全プラグインが導入されている |
| 2 | どのマシンでも、版の記録どおりの版のプラグインが入る | 新規に導入したマシンで、各プラグインの版が版の記録と一致する |
| 3 | 所有者がプラグインの版を更新し、その結果を版の記録としてリポジトリに残せる | 更新の操作のあと、版の記録が新しい版に変わる |
| 4 | プラグインの新しい版を自動で取り込まない | 所有者が更新の操作をしない限り、プラグインの版が変わらない |
| 5 | プラグインを、使うときに読み込む | 起動直後に読み込まれていないプラグインがあり、対応する操作をすると使える |
| 6 | 取得時に組み立てが必要なプラグインも、所有者が道具を手作業で導入せずに使える | 導入直後に、組み立てが必要なプラグインを使える |
| 7 | プラグインの設定の誤りを、変更のたびに自動で見つける | 変更のたびに、起動時のエラーとプラグインの定義の形式が自動で確かめられる |
| 8 | プラグインの新しい版を、週に1回まとめて所有者に知らせる | 新しい版があるとき、週に1回、版の記録を新しい版に書き換える変更の提案が1つ作られる |

要求1の初回起動には、ネットワークへの接続が必要である。
「最小限」では、要求1で揃う全プラグインは、メモとタスクの管理に使うプラグインを指す。版の記録は「すべて」と共通とする。
要求8の変更の提案は、所有者が取り込むまで版を変えないため、要求4と両立する。
起動時にエラーが出ないことは、PRD 0002 の要求3で定める。

### 成功条件の測定方法

新規のマシンまたは復旧したマシンに導入したとき、所有者が要求1から6の受入条件を手作業で一つずつ確かめる。
要求7の受入条件は、変更のたびに自動で確かめる。
要求8の受入条件は、変更の提案が作られるたびに、所有者が確かめる。

### 展開計画

所有者のマシンだけに提供する。
段階的な公開はしない。
版の記録の更新は、新規に導入するマシンと、プラグインを取得し直したマシンに反映される。
