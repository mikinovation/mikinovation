# ADR: ドキュメントハブの日本語検索に文字 bigram のトークナイザーを使う

ドキュメントハブで日本語の全文検索をどう実現するかの決定を記録する。
VitePress 標準の検索を使い、トークナイザーを文字 bigram に差し替える。

- 読者: 開発者
- 状態: 採用
- 決定日: 2026-10-06

用語は PRD 0010 および ADR 0017 と同じ意味で使う。
ドキュメントハブ（以下、ハブ）は、`docs/` の Markdown を Web 上で閲覧できるようにするサイトを指す。
トークナイザーは、検索のために文を語の単位に区切る関数を指す。
文字 bigram は、文を先頭から1文字ずつずらしながら、2文字ずつ区切る方法を指す。たとえば「全文検索」は「全文」「文検」「検索」に区切る。

## 背景

ADR 0017 で、ハブの生成に VitePress を使うと決めた。
VitePress 標準の検索（MiniSearch）は、日本語を分かち書きしない。
そのため、標準のままでは PRD 0010 の機能要求2（日本語のキーワードによる全文検索）を満たせない。
ADR 0017 では、検索の方式を別の ADR で決めることにしていた。

## 制約

選べる案は、次の条件を満たす必要がある。

- 機能要求2の受入条件を満たす。受入条件は、既存の文書の本文にある日本語の語で検索すると、その文書が結果に出ることである。
- 文書の書き方を変えない。
- 所有者一人で保守でき、運用費をかけない。

## 決定

VitePress 標準の検索（MiniSearch）を使う。
MiniSearch のトークナイザーを、文字 bigram で区切る関数に差し替える。

## 決定理由

- 文字 bigram は辞書による分割の結果に左右されない。本文にある2文字以上の語なら、文中のどこを切り出して検索しても一致する。そのため、受入条件を確実に満たせる。
- トークナイザーを差し替えるだけで済み、検索画面も標準のものを使える。追加の依存や外部のサービスが要らないため、一人で保守し、運用費をかけないという制約を守れる。
- 文書は数十本の規模なので、文字 bigram で索引が大きくなっても問題になりにくい。

## 代替案

次の案は、それぞれの理由で採らない。

- `Intl.Segmenter` で単語に分割する案: 辞書による分割に頼るため、複合語の一部で検索すると一致しないことがある。たとえば「全文検索」が1語として索引されると、「検索」では引けない。受入条件を外すおそれがある。
- Pagefind を使う案: VitePress の検索画面とは別のツールを組み込み、保守することになる。
- Algolia DocSearch を使う案: 申請が要り、外部のサービスに依存する。一人で保守し、運用費をかけないという制約から外れる。

## 結果

- 索引を作るときと検索するときに、同じトークナイザーを使う必要がある。トークナイザーの関数を自作し、保守する。
- 索引は単語単位で区切る場合より大きくなり、ページと一緒に配信する量が増える。
- 関係の薄い文書も、検索結果に混ざりやすくなる。
- 1文字だけの検索をどう扱うかと、英数字の語を2文字ずつ区切るかどうかは、この ADR では決めていない。設計書で決める必要がある。
