# ADR: Nix のない環境ではプロジェクトスキルとセッション開始時のプラグイン導入で作業手順を配る

Nix のない環境でも、このリポジトリで作業手順を呼び出せるようにする決定を記録する。
自作の作業手順はプロジェクトスキルとして置き、外部の作業手順はセッションの開始時にプラグインとして導入する。

- 読者: 開発者
- 状態: 採用
- 決定日: 2026-10-06

用語は PRD 0004 と同じ意味で使う。
作業手順は、特定の作業のときにエージェントが呼び出す、決まった手順の定義を指す。
Nix のない環境は、ブラウザとスマホから使う Claude Code のように、このリポジトリの導入操作を行えない環境を指す。

## 背景

ADR 0004 の決定により、作業手順は Home Manager で `~/.claude/skills` に配置する。
Nix のない環境ではこの配置が行われず、ユーザーの設定も読まれない。
そのため、PRD 0004 の要求17 を満たせない。

自作の作業手順は `packages/claude-skills/skills` にある。
リポジトリのルートの `.claude-plugin/marketplace.json` で、プラグインのマーケットプレイスとしても公開している。
自作の作業手順は、tanteki、yomiyasu、mattpocock/skills の `grilling`、公式の commit-commands の `commit` を呼ぶ。
これらは外部の提供元にあり、同じマーケットプレイスからプラグインとして入れられる。

プロジェクトの設定 `.claude/settings.json` でマーケットプレイスとプラグインを有効にしても、Nix のない環境ではプラグインが導入されなかった。
2026-10-06 に始めたセッションでは、導入済みのプラグインが一つもなかった。

## 制約

PRD 0004 の要求17 から、選べる案は次の条件を満たす必要がある。

- Nix のない環境でこのリポジトリを開くと、手作業の設定なしに自作の作業手順と、それらが呼ぶ外部の作業手順が一覧に現れ、呼び出せる。
- 作業手順が呼ぶ側の手順を書き換えずに済むよう、呼ばれる作業手順を名前で呼べる。

あわせて、次の条件を満たす必要がある。

- 自作の作業手順の正本は `packages/claude-skills/skills` の一か所に保つ。
- Nix で導入したマシンの振る舞いを変えない。

## 決定

自作の作業手順と外部の作業手順で、配り方を分ける。

- 自作の作業手順: `.claude/skills/<名前>` に、`packages/claude-skills/skills/<名前>` を指すシンボリックリンクを置く。Claude Code はこれをプロジェクトスキルとして読み込み、名前空間なしの名前で呼べる。このリポジトリでは `mikinovation-skills` プラグインを有効にしない。
- 外部の作業手順: 4つのプラグインを `.claude/settings.json` の `enabledPlugins` で有効にする。対象は tanteki、yomiyasu、mattpocock-skills、commit-commands である。
- 導入: SessionStart のフック `.claude/hooks/session-start.sh` を置く。フックは `.claude/settings.json` に書いたマーケットプレイスを追加し、有効にしたプラグインをプロジェクトのスコープで導入する。フックは `CLAUDE_CODE_REMOTE` が `true` のときだけ動き、導入が終わるまでセッションを待たせる。`claude plugin` のコマンドが書き直す `.claude/settings.json` は、フックの終了時に元の内容へ戻す。

## 決定理由

- シンボリックリンクにすると、正本を一か所に保ったまま、作業手順の変更が導入操作なしに効く。
- プロジェクトスキルは、Nix で配置した場合と同じ名前で呼べる。プラグインにすると `mikinovation-skills:create-prd` のように名前空間が付き、Nix で導入したマシンでは同じ作業手順が二重に並ぶ。
- 外部の作業手順はこのリポジトリの外にあるため、シンボリックリンクでは置けない。プラグインなら、提供元から取り込む記述を持たずに済む。
- プロジェクトの設定だけではプラグインが導入されないため、導入を明示的に行う場所が要る。SessionStart のフックはセッションのたびに走り、リポジトリに置ける。
- フックはマーケットプレイスとプラグインの一覧を `.claude/settings.json` から読む。一覧を一か所に保つため、フックに書き写さない。
- 導入の前に作業手順が呼ばれて失敗しないよう、フックは同期で走らせる。

## 代替案

次の案は、それぞれの理由で採らない。

- `mikinovation-skills` プラグインをこのリポジトリでも有効にする案: 名前空間が付き、Nix で導入したマシンでは同じ作業手順が二重に並ぶ。また、プロジェクトの設定だけでは導入されない。
- 自作の作業手順を `.claude/skills` に複製する案: 正本が二か所になり、内容が食い違いうる。
- 外部の作業手順をリポジトリに取り込む案: 上流ごとの複製を保守することになる。提供元ごとのライセンスの扱いも確かめることになる。
- フックを非同期で走らせる案: セッションは早く始まるが、導入が終わる前に作業手順を呼ぶと失敗する。
- フックにプラグインの一覧を直接書く案: 一覧が `.claude/settings.json` と二か所になる。

## 結果

- Nix のない環境では、マーケットプレイスとプラグインを取り込み終えるまでセッションが始まらない。
- マーケットプレイスは外部のプラグインの版を固定しないため、Nix のない環境では、新しいセッションごとに上流の最新が入る。Nix で導入したマシンとは、作業手順の版が食い違いうる。
- フックは、Nix のない環境に `jq` と `claude` のコマンドがあることに依存する。
- 自作の作業手順を追加したときは、シンボリックリンクも手作業で追加する。追加し忘れると、Nix のない環境ではその作業手順を呼び出せない。
- Nix で導入したマシンでこのリポジトリを開くと、同じ名前の作業手順がユーザーとプロジェクトの両方に置かれる。導入操作をやり直すまでは、両者の内容が食い違いうる。
- フックの変更は、既定のブランチへ取り込んだあとに始めたセッションから効く。
- このリポジトリ以外のリポジトリで Nix のない環境に作業手順を配るには、そのリポジトリにプロジェクトの設定とフックを手作業で追加する。
