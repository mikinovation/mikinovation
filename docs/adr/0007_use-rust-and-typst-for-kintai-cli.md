# ADR: 勤怠表の CLI を Rust で書き、Typst を組み込んで PDF を生成する

勤怠表と請求書を作る CLI `kintai` を Rust で書き、Typst をライブラリとして組み込んで勤怠表 PDF を生成するという決定を記録する。

- 読者: 技術責任者、開発者、将来の保守者
- 状態: 採用
- 決定日: 2026-10-03

用語は PRD 0007 と同じ意味で使う。
案件、打刻、日ごとの見出し、勤怠表、精算幅、稼働率、日割り月、下書き、skill の意味は PRD 0007 による。
テンプレートは、勤怠表の見た目を定める Typst のファイルを指す。
「すべて」「最小限」は、PRD 0001 が定める導入範囲を指す。

## 背景

PRD 0007 は、日々の打刻から月末の勤怠表 PDF と freee の下書きまでを、案件ごとの精算のルールに従って作ることを求める。
その解決案として、計算は CLI が行い、skill が窓口になる案を採った。
そのため、CLI を書く言語と、勤怠表 PDF を生成する方式を決める必要がある。

## 制約

PRD 0007 と ADR 0001 から、選べる案は次の条件を満たす必要がある。

- 丸め、精算、日割りの計算が毎回同じ結果になり、ユニットテストで守れる。
- 勤怠表の見た目を、計算の処理を変えずに差し替えられる。
- 日本語を含む表を PDF に組める。
- Org 形式のファイルにある CLOCK 行とプロパティを読める。
- 導入範囲「すべて」で、所有者のマシンに Home Manager で導入できる。

## 決定

CLI `kintai` を Rust で書き、このリポジトリの `packages/kintai` に cargo のクレートとして置く。

勤怠表 PDF は、`typst` と `typst-pdf` のクレートを組み込んで生成する。
CLI は集計結果をテンプレートに渡すだけにし、見た目はすべてテンプレートが担う。
既定のテンプレートはバイナリに同梱し、案件の設定で別のテンプレートに差し替えられるようにする。
日本語のフォントには Noto Sans JP を使い、バイナリに同梱する。

Org 形式の解析は、CLOCK 行と日ごとの見出しのプロパティに限り、正規表現で行う。

導入は、`buildRustPackage` で nix のパッケージにし、Home Manager で行う。

## 決定理由

- Rust は単一のバイナリを作れるため、実行時に Node や Python などの実行環境を用意しなくて済む。Home Manager でバイナリを置くだけで導入でき、導入の制約に合う。
- Typst は Rust で書かれているため、ライブラリとして組み込める。外部のコマンドに頼らず、単一のバイナリのまま PDF を生成できる。
- 集計結果をテンプレートに渡す形にすると、計算は Rust の中に、見た目はテンプレートの中に分かれる。計算はユニットテストで守り、見た目は計算の処理を変えずに差し替えられる。
- Typst は日本語を含む表を組めるため、日本語の表の制約に合う。フォントを同梱すれば、マシンに入っているフォントにかかわらず同じ見た目になる。
- 読む必要があるのは CLOCK 行とプロパティだけなので、正規表現で足りる。

## 代替案

次の案は、それぞれの理由で採らない。

- TypeScript と Typst: 実行に Node が要り、単一のバイナリにならない。Typst を組み込めず、外部のコマンドとして呼ぶことになる。
- Python: Python と依存ライブラリの実行環境が要る。
- HTML を Chromium で PDF にする案: Chromium が要り、重い。改ページや印刷時のレイアウトの調整が難しい。
- `printpdf` などで PDF をコードから描画する案: 見た目がコードに埋め込まれ、計算の処理を変えずに見た目を差し替えるという制約を満たさない。
- Rust から `typst` のコマンドを呼ぶ案: 実行時に別のコマンドが要り、単一のバイナリにならない。
- `orgize` などの Org 形式の解析ライブラリ: 読むのは CLOCK 行とプロパティだけで、依存を増やすほどの利点がない。
- フォントをマシンから探す案: マシンによって見た目が変わり、フォントがなければ失敗する。
- 各マシンで `cargo install` を実行して導入する案: マシンごとの手作業が残り、ADR 0001 の宣言的な管理から外れる。

## 結果

- 開発には Rust のツールチェーンが要る。「すべて」には rustup が入るが、「最小限」では kintai を使えない。
- `typst` のクレートは API が安定していないため、版を上げるたびに、組み込む側のコードの追従を引き受ける。
- Noto Sans JP を同梱するため、バイナリが数 MB 大きくなる。OFL のライセンスの表示も同梱する。
- `buildRustPackage` で導入するため、依存のクレートを更新するたびに、nix 側のハッシュも更新する。
- 勤怠表の見た目を変えるには、Typst の書き方の知識が要る。
- Org 形式の解析は、nvim-orgmode が出力する CLOCK 行の書式に依存する。手で書式を崩した行は読めず、エラーになる。
