# ADR: Neovim を既定エディターにする

Neovim を既定エディターにし、本体、設定、周辺ツールを Home Manager で管理するという決定を記録する。
導入範囲「最小限」には、メモとタスクの管理に絞った Neovim を含める。

- 読者: 開発者
- 状態: 採用
- 決定日: 2026-09-28

## 背景

PRD 0002 は2つの問題を挙げる。
エディターと言語ごとの補完や診断をマシンごとに手作業で揃えると、マシン間で設定がずれる。
エディターだけで開発作業を終えられないと、別のアプリへ切り替えるたびに作業が途切れる。
所有者は端末とシェルを中心に作業し、Vim 系のモード型の操作に慣れている。

導入範囲「最小限」は、壊れた環境でもすぐに作業を始めるための範囲である。
壊れた環境の復旧でも、Git のコミットメッセージの入力や設定ファイルの修正にエディターが要る。
メモとタスクも ADR 0006 で Neovim に置いているため、「最小限」にエディターがないと扱えない。

## 制約

PRD 0002 の要求から、選べる案は次の条件を満たす必要がある。

- ほかのツールが文章の入力を求めるときに開く、既定のエディターとして使える。
- 初回起動で、所有者が操作せずに編集機能が揃う。
- 日常的に使う言語で、補完、診断、整形、定義への移動、名前の変更を使える。
- ファイルの検索とツリー表示を、エディター内で行える。
- Git の操作とコンフリクトの解消、GitHub の Issue と PR の表示を、エディター内で行える。
- テストの実行、データベースへの問い合わせ、HTTP リクエストの送信、端末の開閉、メモとタスクの管理を、エディター内で行える。
- AI の入力補完と、ファイルや選択範囲の AI への送信を使える。
- 導入範囲「最小限」でも、既定のエディターとして使え、メモとタスクを管理できる（PRD 0002 の要求21）。
- 導入範囲「最小限」を軽く保つ。言語サーバーや、メモとタスクに関係のないプラグインと道具を入れない。

PRD 0001 の要求と ADR 0001 の決定から、次の条件も満たす必要がある。

- macOS、WSL、それ以外の Linux で同じ操作で導入できる。
- 何度導入しても同じ状態になる。

## 決定

Neovim を既定エディターにする。
Neovim は ADR 0001 の共通の Home Manager 設定から、`packages/dotfiles/nix/programs/neovim` のモジュールとして導入し、導入範囲「すべて」と「最小限」の両方に含める。

- 環境変数 `EDITOR` と `VISUAL` を `nvim` にし、`vi`、`vim`、`vimdiff` を Neovim の別名にする。
- 設定は Lua で書き、Home Manager が `~/.config/nvim` に配置する。
- 言語サーバー、formatter、linter、tree-sitter のパーサーのビルドに使うツールは、Neovim の追加パッケージとして Nix で導入する。
- 制約に挙げた編集機能と開発作業は、プラグインで Neovim 内に収める。
- プラグインは lazy.nvim で管理し、版は ADR 0014 のとおり各プラグインの定義の `commit` で固定する。
- 両方の導入範囲で共通の設定を `core.lua` と `core_keymaps.lua` に置く。`core.lua` は leader、オプション、クリップボードを設定し、`core_keymaps.lua` は Neovim に組み込まれた機能だけを使うキーマップを設定する。
- `plugins.lua` は、lazy.nvim を取得して起動する `setup(specs)` と、「すべて」の定義の一覧を返す `full_specs()` を持つ。

導入範囲ごとの違いは次のとおり。

| | すべて | 最小限 |
|---|---|---|
| 入口 | `init.lua` | `minimal.lua`（`init.lua` として配置） |
| 読み込むプラグイン | `full_specs()` の全定義 | nvim-orgmode と org-roam.nvim の定義だけ（ADR 0006） |
| 言語サーバーとキーマップ | 全部を読み込む | `core_keymaps.lua` だけ |
| 追加パッケージ | 言語サーバー、formatter、linter、組み立ての道具 | C コンパイラーだけ |
| `~/.config/nvim` に置くもの | `nvim` ディレクトリー全体 | `minimal-config-files` に挙げたファイルだけ |

- 「最小限」のファイルは、Nix の `linkFarm` で1つのディレクトリーにまとめて配置する。
- C コンパイラーは、nvim-orgmode が tree-sitter-org を組み立てるために使うため、両方の導入範囲に入れる。Linux は gcc、macOS は clang とする。
- 起動確認のスクリプトは、同じ `minimal-config-files` から「最小限」の配置を組み立て、空のデータのディレクトリーでプラグインを取得したあと、エラーなく起動することを確かめる。

## 決定理由

- 端末内で動くため、端末中心の作業に合い、macOS、WSL、それ以外の Linux の端末から同じ操作で使える。
- 本体、設定、周辺ツールを Home Manager で宣言できるため、どの OS でも同じ版と同じ設定になり、何度導入しても状態が変わらない。
- 設定を Lua で書くため、luacheck と busted で設定を検証できる。
- 言語サーバーのクライアントと tree-sitter を内蔵しており、プラグインも豊富なため、補完、デバッグ、テストの実行をエディター内で行える。
- 「最小限」にも同じエディターを入れ、共通の設定を同じファイルから読み込むため、導入範囲によって操作やオプションがずれない。
- 「最小限」のプラグインの定義を「すべて」と共有するため、版の固定と Renovate による更新の通知が両方で同じになる。
- Home Manager の Neovim モジュールは、プロバイダーを無効にする `init.lua` を自動で生成する。「すべて」ではディレクトリーごと配置するため、この生成物はリポジトリの `init.lua` に隠れる。「最小限」もディレクトリーごと配置すれば、同じ仕組みで隠れ、配置先の衝突が起きない。
- 配置するファイルの一覧を1つのファイルにまとめるため、Nix の配置と起動確認が同じ一覧を使い、一覧の漏れを CI で見つけられる。起動確認は空のデータのディレクトリーで動くため、「すべて」で取得済みのプラグインに隠れて漏れを見逃すこともない。

## 代替案

次の案は、それぞれの理由で採らない。

- VS Code: 端末の外で動くため、端末中心の作業に合わない。
- Cursor: 次の2点から採らない。
  - 端末の外で動くため、端末中心の作業に合わない。
  - AI の入力補完と選択範囲の送信は Neovim でもプラグインで満たせるため、エディターに組み込まれた AI 機能は Cursor を選ぶ理由にならない。
- Vim: 設定を Lua で書けないため、luacheck や busted で設定を検証できない。
- Emacs: 所有者は Vim 系のモード型の操作を使いたいが、Emacs でその操作を使うには evil などのプラグインが必要になる。
- IntelliJ IDEA: 次の2点から採らない。
  - 端末の外で動くため、端末中心の作業に合わない。
  - 設定を IDE の中で変更するため、宣言的に管理しにくい。
- 「最小限」に Neovim を含めない案: 壊れた環境の復旧でエディターを使えず、メモとタスクも扱えない。
- 「最小限」の Neovim をプラグインなしにする案: ネットワークなしで起動できるが、メモとタスクを扱えない。
- 「最小限」にも「すべて」と同じ設定を配置する案: 70を超えるプラグインと、その組み立てに使う Rust、Node.js、luarocks などの道具が要り、「最小限」が重くなる。
- 「最小限」では `vim` や `nano` など別のエディターを既定にする案: 導入範囲によって操作が変わり、オプションやキーマップを別に保守する必要がある。
- 環境変数で `init.lua` の動きを切り替える案: シェルを経由しない起動では環境変数がなく、「最小限」でも全プラグインを取得しようとする。
- 「最小限」のファイルを1つずつ `~/.config/nvim` 配下に配置する案: Home Manager が生成する `init.lua` と配置先が衝突し、評価時にエラーになる。

## 結果

- 導入範囲「最小限」の環境にも Neovim が入り、`EDITOR` が設定される。ただし、補完、診断、ファイルの検索、Git の操作など、メモとタスク以外のプラグインと言語サーバーに頼る機能は使えない。
- 「最小限」には C コンパイラーが入る。
- 「最小限」で使う設定を足すときは、`minimal-config-files` に加える必要がある。加え忘れると、起動確認で見つかる。
- `core.lua` と `core_keymaps.lua` にプラグインに頼る設定を書くと、「最小限」の起動でエラーになる。起動確認で見つかる。
- プラグインは Nix ではなく lazy.nvim が初回起動時に取得するため、両方の導入範囲で、初回起動にはネットワークへの接続が必要になる。
- 言語サーバーなどの周辺ツールのうち nixpkgs にないものは、自前のパッケージとして定義し、保守する。
- OS のクリップボードとの共有は WSL と macOS でだけ設定し、それ以外の Linux では設定しない。
