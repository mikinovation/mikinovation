# ADR: 案件の設定は、非公開のリポジトリに案件ごとの TOML ファイルで書く

`kintai` が読む案件の設定を、勤怠の記録と同じ非公開のリポジトリに、案件ごとの TOML ファイルとして置くという決定を記録する。

- 読者: 開発者
- 状態: 採用
- 決定日: 2026-10-03

用語は PRD 0007 と同じ意味で使う。
案件、打刻、日ごとの見出し、精算幅、稼働率、日割り月の意味は PRD 0007 による。
`kintai` は、ADR 0007 で Rust で書くと決めた CLI を指す。
テンプレートの意味は ADR 0007 による。

## 背景

PRD 0007 の要求4は、精算のルールを案件ごとに設定できることを求める。
設定する項目には、契約期間、月額、精算幅、超過単価、控除単価、丸めの単位と向き、休憩の既定値、締め日、請求の項目がある。
要求5は、日割り月の稼働率と精算幅を月ごとに上書きできることを求める。
ADR 0007 では、テンプレートを案件の設定で差し替えられるようにすると決めた。
ADR 0009 では、1Password の参照先を設定で指定すると決めた。
これらを書く形式と置き場は決まっていない。

## 制約

PRD 0007 と ADR 0007 から、選べる案は次の条件を満たす必要がある。

- 非公開のリポジトリに置く。
- 月ごとの上書きや請求の項目のような、入れ子と一覧を表せる。
- Org 形式の解析は、CLOCK 行と日ごとの見出しのプロパティに限る。

## 決定

案件の設定は、勤怠の記録を書く Org 形式のファイルと同じ非公開のリポジトリに、案件ごとの TOML ファイルとして置く。
日割り月の上書き、テンプレートの差し替え、1Password の参照先も、同じファイルに書く。
`kintai` は、`serde` と `toml` のクレートで設定を読む。

## 決定理由

- 型を決めて読めるため、設定の誤りを読み込みの時点で検出できる。
- コメントを書けるため、先方の指示など、値の根拠を設定の横に残せる。
- 表と配列で、月ごとの上書きや請求の項目を表せる。
- Org 形式の解析を、ADR 0007 で決めた範囲にとどめられる。

## 代替案

次の案は、それぞれの理由で採らない。

- Org 形式の案件の見出しのプロパティに書く案: 入れ子や一覧を表しにくく、Org 形式の解析の範囲が広がる。
- YAML で書く案: 暗黙の型変換によって、金額の設定を誤って読む危険がある。

## 結果

- 設定と打刻の記録が別のファイルに分かれるため、Org 形式の側から案件の設定を指し示す手段が要る。
- `toml` のクレートへの依存が増える。
- 設定の項目を変えるときは、TOML の形式と Rust の型を一緒に保守する。
