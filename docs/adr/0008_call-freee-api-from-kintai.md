# ADR: freee の請求書の下書きは kintai が freee の API を呼んで作る

freee の請求書の下書きを、CLI `kintai` が freee の API を直接呼んで作るという決定を記録する。

- 読者: 開発者
- 状態: 採用
- 決定日: 2026-10-03

用語は PRD 0007 と同じ意味で使う。
案件、下書き、skill の意味は PRD 0007 による。
`kintai` は、ADR 0007 で Rust で書くと決めた CLI を指す。

## 背景

PRD 0007 は、対象月の精算額にもとづいて freee に請求書の下書きを作ること（要求11）と、同じ月の下書きを二重に作らないこと（要求14）を求める。
PRD 0007 の解決案では、計算は CLI が行い、skill が窓口になる案を採った。
ただし、freee の API を CLI と skill のどちらから呼ぶかは決めていない。
そのため、下書きを作る担い手を決める必要がある。

## 制約

PRD 0007、ADR 0001、ADR 0004 から、選べる案は次の条件を満たす必要がある。

- 下書きの金額が、CLI の計算結果と必ず一致する。
- 下書きを作るだけで、請求書を先方へ送付しない。
- 対象月の下書きがすでにあれば、新しい下書きを作らずに止まる。
- freee の API の認証の準備は、所有者が引き受ける。
- 導入範囲「すべて」で、所有者のマシンに Home Manager で導入できる。

## 決定

`kintai` が freee の API を呼び、請求書の下書きを作る。
対象月の下書きがすでにあるかの確認も、`kintai` が行う。
skill は `kintai` を呼び、その結果を所有者に報告するだけにする。

## 決定理由

- 金額が Claude を通らないため、下書きの金額は CLI の計算結果と必ず一致する。
- 二重作成の確認が毎回同じ結果になり、ユニットテストで守れる。
- Claude がなくても動き、ADR 0007 で選んだ単一のバイナリのままで済む。

## 代替案

次の案は、それぞれの理由で採らない。

- skill が freee の MCP サーバーを使って下書きを作る案: 下書きの金額を Claude が書き写すため、誤りの余地が残る。二重作成の確認も、Claude の判断で行うことになる。
- 下書きの作成だけを別のスクリプトで行う案: 実行環境がもう1つ要り、単一のバイナリでなくなる。

## 結果

- OAuth のトークンの更新と、freee の API との通信を Rust で実装し、保守する。
- HTTP クライアントのクレートへの依存が増える。
- freee の API が変わったら、`kintai` を追従させる。
- テストでは、freee の API を差し替えて振る舞いを確かめる。
- freee の認証情報の保管先は、別の ADR で決める。
