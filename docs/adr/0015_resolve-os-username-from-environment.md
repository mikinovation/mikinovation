# ADR: 設定する OS のユーザー名を flake に書かず、評価時に環境変数から決める

flake の出力に OS のユーザー名を書かず、導入時の環境変数から設定するユーザーを決めて、同じ出力をどのユーザー名でも使えるようにするという決定を記録する。

- 読者: 技術責任者、開発者、将来の保守者
- 状態: 採用
- 決定日: 2026-10-06

この ADR は、ADR 0001 のうち「ユーザー名を flake の出力に書く」という部分を置き換える。
1つの flake と共通の Home Manager 設定で全 OS の環境を定義するという ADR 0001 の決定は変えない。

## 背景

ADR 0001 は、ユーザー名を flake の出力に書くと決めていた。
そのため、出力ごとにユーザー名が固定されていた。

| OS | 出力 | 固定されていたユーザー名 |
|---|---|---|
| WSL | `nixosConfigurations.nixos` | `nixos` |
| macOS | `darwinConfigurations.mac` | `mikinovation` |
| それ以外の Linux | `homeConfigurations.<ユーザー名>` | `mikinovation` と `nixos` |

マシンのユーザー名が flake に書かれた名前と異なると、そのマシンには導入できない。
新しいユーザー名のマシンで導入するたびに、flake に出力を書き足す必要があった。
それ以外の Linux では、同じ内容の出力がユーザー名の数だけ並んでいた。

## 制約

PRD 0001 と ADR 0001 から、選べる案は次の条件を満たす必要がある。

- macOS、WSL、それ以外の Linux で同じ操作で導入できる。
- 導入範囲を「すべて」と「最小限」から選べる。
- 所有者と異なるユーザー名でも、flake を書き換えずに導入できる。
- CI の `nix flake check` と試し組み立てを、マシンのユーザー名なしで実行できる。

## 決定

flake の出力にユーザー名を書かない。
`packages/dotfiles/nix/flake.nix` は、評価時に次の環境変数を順に読み、最初に見つかった値を設定するユーザー名とする。

| 順 | 環境変数 | 使われる場面 |
|---|---|---|
| 1 | `DOTFILES_USER` | 明示的に指定する場合 |
| 2 | `SUDO_USER` | `sudo nixos-rebuild` と `sudo darwin-rebuild` |
| 3 | `USER` | Home Manager を単体で使う場合 |

値が `root` の環境変数は飛ばす。
どれも見つからない場合は、NixOS-WSL の既定ユーザーである `nixos` を使う。

それ以外の Linux の出力は、ユーザー名ではなく導入範囲で分け、`homeConfigurations.linux` と `homeConfigurations.linux-minimal` の2つにする。
WSL と macOS の出力名は変えない。

環境変数を読むには評価を impure にする必要があるため、`setup.sh` は3つの OS のすべてで `--impure` を付けて適用する。

## 決定理由

- ユーザー名を環境から決めるため、flake を書き換えずにどのユーザー名のマシンにも導入できる。
- `sudo` で実行すると `USER` が `root` になるが、`SUDO_USER` に実行したユーザーが残る。この順で読めば、`sudo` を使う WSL と macOS でも、使わないそれ以外の Linux でも、利用者は同じ操作で導入できる。
- `root` を飛ばすため、root のシェルから実行しても root を通常のユーザーとして設定しない。
- `nix flake check` などの pure な評価では環境変数を読めず、`nixos` に決まる。CI はマシンのユーザー名なしで同じ結果を得る。
- 出力を導入範囲だけで分けるため、出力名から選ぶものが導入範囲だけになり、ADR 0001 の「導入範囲の選択を出力名の選択として扱う」考え方と合う。

## 代替案

次の案は、それぞれの理由で採らない。

- 使うユーザー名ごとに出力を書き足す（従来の方式）: 新しいユーザー名のマシンで導入するたびに flake の変更が要り、同じ内容の出力が増える。
- ユーザー名を `setup.sh` の引数や環境変数として必須にする: 利用者の操作が OS ごとに増える。`sudo` は既定で環境変数を引き継がないため、WSL と macOS では渡し方も変わる。
- ユーザー名を書いた、Git で管理しない設定ファイルを置く: flake は Git で管理していないファイルを読めないため、そのファイルを置けない。
- 全員を固定のユーザー名にそろえる: マシンのユーザー名は、OS の導入時や組織の方針で決まることがあり、所有者が選べない場合がある。

## 結果

- 適用するたびに `--impure` が必要になる。`setup.sh` が付けるが、手動で適用する場合は利用者が付ける。付け忘れると `nixos` として評価され、ユーザー名が異なるマシンでは Home Manager の適用がユーザー名の不一致で失敗する。
- impure な評価では、環境変数がユーザー名を通じて評価結果に影響する。同じ `flake.lock` でも、ユーザー名が違えば別の構成になる。
- それ以外の Linux の出力名が `<ユーザー名>` から `linux` に変わるため、手動で適用する場合の出力名を改める必要がある。
- マシン名とリポジトリの配置先は、この決定の対象外である。WSL の出力名と、リポジトリの配置先の参照は、これまでどおり固定する。
- Git のコミットに使う名前とメールアドレスは OS のユーザー名とは別のものであり、この決定では変えない。
