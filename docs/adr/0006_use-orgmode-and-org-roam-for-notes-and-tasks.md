# ADR: ノートとタスクを Org 形式で書き、nvim-orgmode と org-roam.nvim で扱う

ナレッジノートと開発チケットを Org 形式のファイルで書き、Neovim 上の nvim-orgmode と org-roam.nvim で扱うという決定を記録する。

- 読者: 技術責任者、開発者、将来の保守者
- 状態: 採用
- 決定日: 2026-07-26

用語は PRD 0006 と同じ意味で使う。
ナレッジノート、メタデータ、チケット、手番、アジェンダ、受信箱の意味は PRD 0006 による。
「すべて」「最小限」は、PRD 0001 が定める導入範囲を指す。

## 背景

PRD 0006 は、ノートとチケットの両方に問題を挙げる。
ナレッジノートに種類やタグなどのメタデータがないと、ノートが増えるにつれて、人と AI エージェントのどちらからもノートを探しにくくなる。
メタデータを付けるかどうかを所有者の注意に任せると、付け忘れたノートが残る。
開発チケットは未着手から完了まで11の状態を経るため、状態を順に切り替える操作や、段階ごとの色分けでは扱えない。

所有者は ADR 0002 の決定により、Neovim を既定のエディターにしている。
所有者のナレッジノートは、2026-07-26 にタスクと同じ置き場所から、このリポジトリの `roam/` へ移した。

## 制約

PRD 0006 と ADR 0002 から、選べる案は次の条件を満たす必要がある。

- ナレッジノートとチケットを、Neovim の中で扱える。Emacs でノートとタスクを扱うことは対象外とする。
- タグに複数の値を持てる。
- PRD 0006 の要求1から10を満たす。具体的には、作成時のメタデータの欄、種類の補完、タグのないノートの一覧、ノート同士のリンクとリンク元の表示、一覧からの状態の選択、手番による色分け、状態の順のアジェンダ、受信箱を開く操作、見出しへの ID の付与、Markdown としてのコピーである。
- 導入範囲「すべて」でだけ使え、所有者のマシンだけに提供する。
- ノートとタスクの保管場所は、所有者が事前に用意する。

## 決定

ナレッジノートとチケットを Org 形式のファイルで書き、Neovim 上の次のプラグインで扱う。

- nvim-orgmode: Org 形式の編集、作業状態、アジェンダを担う。
- org-roam.nvim: ナレッジノートの作成、ノート同士のリンク、バックリンクを担う。
- org-bullets.nvim: 見出しの記号を整えて表示する。

プラグインは ADR 0002 の lazy.nvim で取得し、版はほかのプラグインと同じく `lazy-lock.json` で固定する。導入範囲「すべて」にだけ含める。

保管場所は次のとおりとする。

- ナレッジノート: このリポジトリの `roam/`。
- チケットと受信箱: 別リポジトリ `mikinovation/org`。org-roam.nvim は、このリポジトリのファイルもノートとして扱う。

ノートの作成テンプレートは、種類、説明、タグ、作成日時の4欄を、本文に YAML のブロックとして埋め込む。
作成日時は自動で入り、ファイル名は `<作成日時>-<slug>.org` とする。

PRD 0006 の要求のうち、プラグインの標準機能で足りない部分は自作の Lua で補う。

- 種類の補完: blink.cmp の補完元として、YAML の `type:` の行でだけ6つの種類を候補に出す。
- タグのないノートの一覧: Telescope の一覧として、タグの欄がないか空のノートを出す。
- 状態の選択: 標準の状態の切り替えを無効にし、11の状態と「なし」から絞り込んで選ぶ操作に置き換える。
- 色分け: 未着手、所有者の手番、他者の手番を別の色の帯で、完了を目立たない色で表示する。
- アジェンダ: チケットを状態の順に並べる表示を加える。Claude のセッションログを置く `journal/` は対象から外す。
- 受信箱を開く操作、見出しへの ID の付与、選択範囲の Markdown としてのコピーに、キーを割り当てる。Markdown への変換には pandoc を使う。

## 決定理由

- Neovim の中で完結し、プラグインも ADR 0002 の lazy.nvim で、ほかのプラグインと同じく管理できる。エディター内で扱う制約と、Emacs を対象外とする制約に合う。
- Org 形式は見出しに作業状態を持ち、アジェンダで横断的に集められる。そのため、ナレッジノートとチケットを1つの形式と1つのツールで扱える。要求5と要求7がこれに当たる。
- nvim-orgmode は、11の状態のキーワード、状態ごとの色、アジェンダの対象、追加のアジェンダ、標準の状態の切り替えの無効化を、設定として宣言できる。見出しの取得や ID の付与の API も持つため、不足する操作を小さな自作の Lua で補える。要求5、6、7、9がこれに当たる。
- org-roam.nvim は nvim-orgmode の上で動き、リンク、バックリンク、作成テンプレートを提供する。テンプレートにメタデータの YAML を書くことで、ノートは作成時点でメタデータの欄を持ち、タグに複数の値を持てる。要求1と要求4、およびタグの制約がこれに当たる。
- 既存のノートとチケットが Org 形式で書かれているため、移行せずに使える。

## 代替案

次の案は、それぞれの理由で採らない。

- Emacs と org-roam: PRD 0006 は Emacs でノートとタスクを扱うことを対象外とする。採ると、エディターを2つ保守することになる。
- obsidian.nvim などの Markdown のノート: frontmatter でタグに複数の値を持てる。ただし見出しごとの作業状態とアジェンダがないため、チケットに別の仕組みが要る。既存の Org 形式のノートとチケットの移行も要る。
- zk-nvim、telekasten.nvim: Markdown のノートと同じ理由で採らない。
- Neorg: Neovim の中で完結する。ただし独自の形式であり、既存の Org 形式のノートとチケットの移行が要る。
- チケットを GitHub Issues などの外部サービスで管理する案: エディターの中で完結しない。

## 結果

- 「最小限」には Neovim も pandoc も入らないため、ノートとタスクを扱えない。
- 保管場所は `~/ghq/github.com/mikinovation/mikinovation/roam` と `~/ghq/github.com/mikinovation/org` の絶対パスで参照する。このリポジトリと `mikinovation/org` を、それぞれこのパスへ事前に置く必要がある。
- プラグインは lazy.nvim が初回起動時に取得するため、初回起動にはネットワークへの接続が要る。
- メタデータは本文の YAML にあるため、nvim-orgmode と org-roam.nvim の標準のタグ機能からは見えない。タグの読み取りと種類の補完は自作の Lua に頼る。YAML の解析は簡易なもので、インライン形式とブロック形式のリストだけを扱う。テンプレートより前に作ったノートは YAML のブロックを持たないため、タグのないノートの一覧に出る。
- 状態の選択、色分け、補完、一覧の自作の Lua は、nvim-orgmode の API と設定の形式に依存する。上流の変更に合わせて保守を引き受ける。
- 完了状態は1つにまとめるため、受け入れ済み、日常の雑務の完了、中止を区別できない。`journal/` をアジェンダから外すため、そこに残った未完了の見出しはアジェンダに出ない。
- 状態の色は tokyonight の色の値を直接書いているため、配色を変えると色の記述も書き直すことになる。
- ノート同士の関係はバックリンクでしかたどれず、ノート全体の構造は見えない。全体を俯瞰する方法は PRD 0006 の未解決の問いとして残る。
