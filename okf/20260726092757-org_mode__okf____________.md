- org-modeにokfの概念を導入することを検討する。
- org-roamに対してプロパティをどのように付与するかを検討する必要がある
  - プロパティで導入するか、yaml形式で埋め込むか
    1. org-roamのノードに対して、okfの概念を表すプロパティを追加する
    ```
    :PROPERTIES:
    :ID: 31de5fdb-617e-4832-954e-670ae5e2afd6
    :ROAM_ORIGIN: 6df1b481-534b-4f18-92c1-1fe09c7b021b
    :END:
    ```
    2. org-roamのノードに対して、yaml形式でokfの概念を表すプロパティを追加する
    ```
    #+begin_src yaml
    type: note
    description: org-modeにokfの概念を導入した記録
    tags: [issue]
    timestamp: 2026-07-26T09:27:57+0900
    #+end_src
    ```
  - 結論2を採用
    - org-roamだと一つのプロパティに対して、複数の値を持たせることができないため、yaml形式で埋め込む方が柔軟性が高い
- ymlを埋め込むタイミングをどうするか
  - <leader>ncで新規ノードを作成する際に、ymlを埋め込むようにする
  - org-roamに設定を追加
  ```
  templates = {
    description = "default",
      template = table.concat({
      "#+begin_src yaml",
      "type:",
      "description:",
      "tags: []",
      "timestamp: %<%Y-%m-%dT%H:%M:%S%z>",
      "#+end_src",
      "",
      "%?",
    }, "\n"),
    target = "%<%Y%m%d%H%M%S>-%[slug].org",
  },
  ```
- typeやtagsの値をどのように補完するか
  - nvim-cmpを使って補完する
- ビジュアライズをどうするか
  - org-roam.nvim(chipsenkbeil/org-roam.nvim)本体にグラフ表示機能は無い
    - README上で org-roam-graph 拡張は "Unimplemented for now" と明記されている
    - 現状はノードバッファ(<leader>nl / <leader>nb)によるbacklink表示と、quickfixリストへの展開のみ
    - Emacsのorg-roam-uiはsqlite DBに依存しており、sqliteを使わないNeovim版には流用できない
  - 案を比較
    1. 標準機能(ノードバッファ + quickfix)で妥協する
       - 追加実装コスト0、Neovim内で完結する
       - 1ノードのbacklink/forward linkしか追えず、全体のグラフ構造は見えない
    2. .orgファイルをスキャンしてmermaid/graphviz形式のグラフを生成するスクリプトを自作する
       - :ID: / :ROAM_ORIGIN: / [[id:...]]リンクを抽出してノードとエッジを構築する
       - 生成結果を別ファイルに出力し、mermaid preview等で確認する
       - 実装・保守コストが発生するが、ノード間の全体構造を俯瞰できる
    3. org-roam-ui相当のWeb UIを自作する
       - フルスクラッチになり実装コストが最も高い
    4. OKF本家(GoogleCloudPlatform/knowledge-catalog)のvisualizeコマンドに載せる
       - `python -m reference_agent visualize --bundle <dir>` で、Cytoscape.js製のforce-directedグラフを自己完結HTML1枚(viz.html)に生成
       - frontmatter(description/resource/tags)と本文をノード詳細パネルに表示、markdownリンクをエッジ、"Cited by"バックリンク、検索、type filter、レイアウト切替(cose/concentric/breadth-first/circle/grid)まで標準搭載
       - 前提条件が今の実装と合わない
         - 本家OKF v0.2はfrontmatterをファイル先頭の`---`ブロックに書く純粋なmarkdown形式だが、今回の実装はorg-modeのsrcブロックとして本文中に埋め込んでいる
         - グラフのエッジは本文中の標準markdownリンク(`[text](/path/to/concept.md)`)から構築される。今のノード間関係はorg-roamの:ID:/:ROAM_ORIGIN:プロパティ(またはorg-roamの[[id:...]]リンク)なので、そのままでは読めない
         - 使うには「orgファイル→OKF markdownバンドル(frontmatter先頭化 + markdownリンクへの変換)」のエクスポートスクリプトが別途必要
       - 本家frontmatterは`generated: { by, at }`のように構造化されたprovenanceフィールドを持つ。今回の`timestamp:`はこれの簡易版で、本家仕様には無いフィールド
  - 結論: 当面は1(標準機能)で運用する
    - ノート数・リンク数がまだ少なく、専用ツールを持つ投資対効果が低いため
    - ノートが増えて全体構造を俯瞰したくなったタイミングで、2、または4(orgをOKFバンドルにエクスポートして本家visualizerに通す)を再検討する
